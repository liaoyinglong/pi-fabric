# Lean subagent routing reference

Lean V2 keeps local one-shot workers plus one bounded recursive Pi primitive. Main decides whether to delegate, creates a temporary semantic role, and selects two orthogonal routing dimensions: execution tier and capability policy.

There are no configured role/profile selectors in this design.

## Model-facing run contract

Run one worker and wait:

```ts
const result = await agents.run({
  tier: "fast",
  policy: "inspect",
  role: "repository scout",
  instructions: "Return only concrete evidence and uncertainty.",
  task: "Locate the reconnect retry implementation.",
});
return result;
```

The public request surface is intentionally small:

```text
task          required, self-contained child task
tier          required: fast | balance | strong
policy        required: inspect | execute | modify | isolated
role          optional temporary semantic responsibility
instructions  optional bounded call-specific instructions
name          optional display name only
timeoutMs     optional bounded timeout override
schema        optional JSON Schema for structured output
```

Main does not pass raw `runner`, `cli`, `model`, `thinking`, `tools`, `extensions`, or `worktree` fields. Tier and policy configuration resolve them internally.

## Built-in tiers

```text
fast     cheap bounded discovery/repetitive inspection
balance  routine reasoning/debugging/implementation/verification
strong   ambiguous/high-impact/difficult reasoning/independent review
```

Default routing:

```yaml
tiers:
  fast:
    runner: pi
    model: cliproxyapi/gpt-5.6-luna
    thinking: medium

  balance:
    runner: pi
    model: cliproxyapi/gpt-5.6-terra
    thinking: medium

  strong:
    runner: pi
    model: cliproxyapi/gpt-5.6-sol
    thinking: medium
```

AGY and Droid remain available as CLI runner overrides. They are not part of the built-in tier mapping.

Routing rule: use the lowest tier that can reliably complete the bounded task. Escalate only when evidence is insufficient, uncertainty remains material, or the task is harder than expected.

## Built-in capability policies

```yaml
policies:
  inspect:
    tools: [read, grep, find, ls]
    worktree: false

  execute:
    tools: [read, grep, find, ls, bash]
    worktree: false

  modify:
    tools: [read, grep, find, ls, bash, edit, write]
    worktree: false

  isolated:
    tools: [read, grep, find, ls, bash, edit, write]
    worktree: true
```

Policies are hard capability boundaries, not personas. `inspect` is the normal research/review boundary. `execute` adds tests/builds/diagnostics without source edits. `modify` permits a scoped implementation in Main's current workspace. `isolated` permits mutation in a separate Git worktree.

Policy resolution happens after tier/call routing so a call cannot silently broaden its own tool or worktree boundary.

## Temporary roles and instructions

Roles are generated by Main for the task at hand:

```ts
return agents.run({
  tier: "strong",
  policy: "inspect",
  role: "architecture critic",
  instructions: "Challenge the proposed boundary. Report only supported concerns and residual risk.",
  task: "Review the proposed cache invalidation design.",
});
```

A role is prompt context only. It never selects a model, runner, or tool grant.

Each child also receives the built-in output contract:

- return a compact result rather than a tool transcript;
- include concrete evidence, changed files, or verification results when relevant;
- state uncertainty, missing evidence, and blockers explicitly;
- do not broaden scope beyond the assigned task.

## Routing configuration

Global files:

```text
~/.pi/agent/fabric/subagents.yaml
~/.pi/agent/fabric/subagents.yml
~/.pi/agent/fabric/subagents.json
```

Trusted project files:

```text
.pi/fabric/subagents.yaml
.pi/fabric/subagents.yml
.pi/fabric/subagents.json
```

Optional host-supplied file:

```text
PI_FABRIC_SUBAGENTS_FILE=/absolute/path/to/subagents.yaml
```

The only recognized top-level routing keys are `tiers` and `policies`:

```yaml
tiers:
  fast:
    runner: cli
    cli: droid
    model: droid/custom-fast
    thinking: medium
    instructions: Prefer exact file references.

  strong:
    transport: herdr

policies:
  inspect:
    tools: [read, grep]
    instructions: Inspect only the smallest relevant surface.

  isolated:
    worktree: true
```

Tier overrides can set `description`, `instructions`, `runner`, `cli`, `transport`, `model`, `thinking`, `timeoutMs`, and `extensions`.

Policy overrides can set `description`, `instructions`, `tools`, and `worktree`.

Project definitions merge over global defaults/overrides field-by-field only when Pi trusts the project. `PI_FABRIC_SUBAGENTS_FILE` loads last. Old `roles:` objects are not interpreted as routing configuration.

Inspect active semantics when necessary:

```ts
return agents.routing({});
```

`agents.routing()` returns tier descriptions plus policy tool/worktree boundaries and the loaded override sources. It intentionally omits raw model and runner values from the model-visible result.

## Spawn and wait

Start a detached worker:

```ts
const handle = await agents.spawn({
  tier: "fast",
  policy: "inspect",
  role: "upstream researcher",
  task: "Check the upstream contract and return bounded evidence.",
});

const localWork = await pi.grep({ pattern: "unsafe", path: "src" });
const research = await agents.wait({ id: handle.id });
return { localWork, research };
```

Retained lifecycle operations:

```text
agents.wait({ id })
agents.status({ id })
agents.list({})
agents.stop({ id })
agents.cleanup({ id, deleteBranch? })
```

Detached runs can notify Main on completion when `agents.notifyOnComplete` is enabled. Calling `wait()` makes the run foreground work for the current program.

## Steering and follow-up

Running Pi/Claude children can be redirected between turns:

```ts
const handle = await agents.spawn({
  tier: "strong",
  policy: "inspect",
  role: "failure investigator",
  task: "Investigate the authentication failure.",
});

await agents.steer({
  id: handle.id,
  message: "Ignore token rotation; focus on cookie/session lifetime.",
});

return agents.wait({ id: handle.id });
```

Controls:

```text
agents.steer({ id, message, data? })
agents.followUp({ id, message, data? })
agents.setSteeringMode({ id, mode: "all" | "one-at-a-time" })
agents.setFollowUpMode({ id, mode: "all" | "one-at-a-time" })
```

These target compatible local Pi/Claude children. Generic CLI adapters execute one headless prompt per invocation and reject steering/follow-up.

## Child compaction

`agents.compact({ id, instructions? })` requests advisory compaction for a running Pi child. This is child-session control only; Lean V2 has no Fabric main-session compaction runtime. Claude and CLI adapter runs do not expose this Pi compaction RPC.

## Recursive delegation

Use recursion only when one child context is insufficient:

```ts
return agents.recurse({
  tier: "strong",
  policy: "inspect",
  role: "problem decomposer",
  task: "Decompose this cross-module problem, delegate bounded evidence gathering if needed, and return the verified conclusion.",
});
```

The selected tier must resolve to `runner: pi`. With built-in defaults, `fast`, `balance`, and `strong` all satisfy that requirement. Lean starts an eligible Pi child with recursive Code Mode enabled and returns a compact result containing status, text/value, error, turns, tool-call count, and usage rather than the full internal run record.

Existing guards still apply:

- `agents.maxDepth` limits recursive Pi depth;
- `agents.maxPerExecution` / top-level `agentBudget` cap agent starts in the current `fabric_exec`;
- child timeouts and `maxTokensPerChild` apply;
- the selected policy continues to bound tools and worktree behavior;
- `agents.budgetUsd` shares a cost ledger across recursive Pi descendants when configured.

Use ordinary `run`/`spawn` for normal delegation. `agents.recurse` is a primitive, not a replacement workflow engine.

## Runner and transport notes

Pi, Claude, and supported CLI adapters remain execution backends, but Main selects them indirectly through tiers.

Supported first-party CLI adapters are:

```text
agy    Antigravity CLI
droid  Factory Droid CLI
```

Tier configuration can select `runner: cli` plus `cli: agy|droid`; if `cli` is omitted, `agents.cli.adapter` supplies the adapter. Per-adapter executable/model defaults remain under `agents.cli.agy` and `agents.cli.droid`.

Runner and transport remain independent tier settings:

```text
runner:    pi | claude | cli
transport: process | tmux | screen | localterm | herdr | auto
```

Droid maps portable tool grants to native Droid tool IDs and uses native restriction flags. Antigravity currently receives Fabric's requested tool list as an explicit prompt boundary while its own CLI permission configuration remains authoritative; Fabric does not enable a dangerous permission bypass automatically.

CLI adapters are one-shot and do not support recursion, steering/follow-up, or Fabric-triggered compaction.

## Structured results

Pass `schema` when Main needs machine-readable output:

```ts
const result = await agents.run({
  tier: "fast",
  policy: "inspect",
  role: "file inventory analyst",
  task: "Find the files responsible for authentication.",
  schema: {
    type: "object",
    properties: {
      files: { type: "array", items: { type: "string" } },
    },
    required: ["files"],
    additionalProperties: false,
  },
});
return result.value;
```

Use schemas only when structured aggregation materially helps. Free-form compact text is preferable for ordinary findings and review conclusions.
